## First committed application

The earliest independently verified repository event is the parentless [root commit 347082726a97c90af337a352b4c25b5f85acc115](https://github.com/jeremyrunningphotography/lightflow-studio/commit/347082726a97c90af337a352b4c25b5f85acc115), dated **July 22, 2026, 5:39:34 p.m. PDT**, titled “Initial Jeremy Media Toolkit v0.2.” GitHub [repository metadata](https://api.github.com/repos/jeremyrunningphotography/lightflow-studio) records creation at July 23, 00:40:20 UTC: **July 22, 5:40:20 p.m. PDT**. The kickoff's July 23 repository date uses UTC. Git timestamps do not date the first idea, first source draft, or a successful binary run.

The [v0.2 README](https://github.com/jeremyrunningphotography/lightflow-studio/blob/347082726a97c90af337a352b4c25b5f85acc115/README.md) describes a native .NET 8/WPF Windows utility for Jeremy Running Photography video workflows. The [initial tree](https://github.com/jeremyrunningphotography/lightflow-studio/tree/347082726a97c90af337a352b4c25b5f85acc115) contains the application, experimental Premiere helper, README, and PowerShell build/run/publish scripts, but no test project. Its [project file](https://github.com/jeremyrunningphotography/lightflow-studio/blob/347082726a97c90af337a352b4c25b5f85acc115/JeremyMediaToolkit/JeremyMediaToolkit.csproj) declares version 0.2.0.

The first committed feature set includes folder batch encoding with .cube LUT selection, resolution options, NVIDIA H.264 NVENC, FFmpeg/FFprobe discovery, progress and resume, normal/salvage/video-only modes, metadata inspection, full-decode verification, MP4 rewrap, 1080p proxies, and contact sheets. The README and [implementation](https://github.com/jeremyrunningphotography/lightflow-studio/blob/347082726a97c90af337a352b4c25b5f85acc115/JeremyMediaToolkit/MainWindow.xaml.cs) support this source inventory. The README warns that missing media cannot be reconstructed and originals are not overwritten. These committed capabilities are consistent with the earlier assistant-reported v0.1 feature list; they do not validate that ZIP or its operation.

The [Premiere helper](https://github.com/jeremyrunningphotography/lightflow-studio/blob/347082726a97c90af337a352b4c25b5f85acc115/PremiereHelper/README.txt) requires a duplicate project and Adobe Media Encoder preset. It establishes an experimental Premiere workflow alongside the standalone app. The initial files do not mention DJI or Kyno; their earlier role comes from the conversation-derived #428 supplement, not from the Git tree.

## AI development: what can be said now

The #428 supplement attributes a v0.1 ZIP claim and a v0.2 WPF ZIP claim to the assistant, while attributing the broader Toolkit and native WPF decisions to user acceptance. That is evidence about the reported human/AI interaction, with transcript and artifact provenance still outstanding. It does not prove the ZIP contents or successful execution.

The first PRs have agent-prefixed heads, beginning with [agent/lut-folder-dropdown](https://github.com/jeremyrunningphotography/lightflow-studio/pull/1). PR descriptions report implementation and validation: #1 reports nine tests and a local self-contained publish; [#2](https://github.com/jeremyrunningphotography/lightflow-studio/pull/2) reports fifty tests and extraction of deterministic logic from WPF. This is contemporary evidence of agent-style branch/PR work and *reported* validation. GitHub attributes commits and PRs to Jeremy's account. Branch names and PR prose alone cannot establish the model, prompts, exact AI contribution, or who made individual design decisions.

The July 24 [backlog tooling](https://github.com/jeremyrunningphotography/lightflow-studio/commit/2d2e4de87a898f91af05eca66ba6d0b3580ba621) and issues are the earliest verified issue-driven planning in this survey. Later [AGENTS.md](https://github.com/jeremyrunningphotography/lightflow-studio/blob/main/AGENTS.md), the [assignment registry](https://github.com/jeremyrunningphotography/lightflow-studio/blob/main/docs/AGENT_ASSIGNMENTS.md), and [PR #382](https://github.com/jeremyrunningphotography/lightflow-studio/pull/382) document explicit names, independent clones, review gates, isolated data roots, and owner acceptance by October. Those later practices cannot be projected back onto July. The full transition belongs to [#429](https://github.com/jeremyrunningphotography/lightflow-studio/issues/429).
