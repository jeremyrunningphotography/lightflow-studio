## Speed and audio

`Player.Speed` accepts 0.125–16 and adjusts Flyleaf's existing clock/decoder scheduling.
Lightflow exposes 0.125, 0.25, 0.5, 1, 2, and 4. Source opens reset to 1.
`MediaPlaybackService.SetReviewOptionsAsync` uses the existing source lifetime,
operation generation, and serialization gate. The backend pauses, settles the current
position, applies options, and resumes when previously playing. Internal option-change
frames are suppressed. Positions and range boundaries remain source-timeline time.

The existing audio companion uses bundled FFmpeg `atempo`, chaining factors in the
0.5–2 interval. There is no new audio decoder architecture, PCM timing engine, or
time-stretch implementation. Output remains 48 kHz stereo with the existing bounded
buffer and volume/mute contract. Every play/restart begins at the settled video PTS.

## Cadence preview

The pinned `VideoDecoder.RecvAVFrame` discards decoded frames using an integer counter
before `Renderer.FillPlanes`. Its effective divisor is
`ceil(speed * sourceFPS / (MaxOutputFps + 1))`. Lightflow places that ratio inside the
chosen divisor bucket and accounts for speed, so changing speed does not change which
fraction of source frames is selected. The decoder-derived selector is refreshed while
paused and queued frames are flushed with the existing seek path.

Choices are exact integer-divisor conversions from actual stream FPS. Integer and
1000/1001 families stay distinct: 120 offers 60/30/24; 119.880… offers
59.940…/29.970…/23.976…; 60 offers 30; 50 offers 25. Non-divisor choices are omitted.
Source uses unthinned presentation rather than Flyleaf's default 60 fps limiter.
Nominal-FPS VFR input cannot promise a uniform target cadence; selection still drops
every Nth decoded frame using real PTS. No synthetic frames or Export conversion occur.

The real-backend test checks every-fifth-frame PTS spacing at all six speeds, source
reset, and adjacent 120 fps stepping after pause. Pausing restores full-frame inspection;
cadence applies during playback. This avoids losing source frames during In/Out placement,
stepping, frame capture, or Preview-frame selection.

## Playback quality investigation

No quality UI ships. The codec still decodes frames before the existing cadence limiter
can discard them. Native zoom/pan changes the renderer viewport after decode. The Color
post-process uses renderer targets; no measured, general-purpose cheaper decode/Color
contract for Full/High/Medium/Low was established. The discarded-frame path can avoid
some plane preparation/render work, but this is neither a resolution-quality contract
nor evidence of a representative playback performance improvement.

No before/after quality benchmark is claimed because no quality mode is proposed.
The small deterministic fixtures above test correctness only. Zoom and cadence are
explicitly display/review controls, not performance settings.

## Presentation and manual acceptance

Player claims native surface input through the Lightflow presentation lease; Flyleaf's
default bindings are disabled only for that claiming consumer. The same gesture owner
handles WPF still/retained frames and the native video Window. Single click waits for
the Windows double-click interval; double click cancels it; dragging cancels clicks.
Chrome and Right Panel are outside that surface route. #244 BrowserGridRows drag
initiation and transition invalidation are unchanged.

Fullscreen temporarily puts the existing Player control in the existing Window's content
slot, retaining the shell and original parent in memory. Exit restores the same shell,
window style/resize/state and Player parent. No source reopen, new window, playback lease,
or Right Panel model is created. Closing restores normal window presentation before
workspace geometry is saved. Controls remain visible for accessibility; idle hiding is
not implemented.

Fit/50%/100%/200%/400% use viewport and source pixel dimensions plus WPF DPI. Video uses
Flyleaf's renderer viewport; still and retained frames use equivalent WPF transforms.
Dragging pans within the image overflow and Ctrl+wheel selects zoom levels. Fit resets pan.
Zoom is centered, not pointer-centered. Non-square-pixel/rotation/display-driver details
remain visual acceptance limitations of the existing presentation paths.

Hands-on scenarios using the packaged executable:

- Video single click while paused/playing; double click and Esc without incidental playback.
- Timeline, volume, Color, menus, and Right Panel do not also toggle playback.
- Pan and fullscreen never show Browser MOVE/file-drag feedback; Browser file/Collection
  drag still works after returning.
- Fullscreen enter/exit during playback and selected Subclip review retains source,
  position, Color/bypass, range, Browser selection, and return path; close from fullscreen.
- Loop full source, working range, and selected Subclip, including slow/fast speeds;
  disable Loop and deliberately seek beyond Out.
- All speeds with speech/music and seeks/pause/resume; change source and confirm 1×.
- Fit and 100% still/video at different Windows DPI settings; drag to pan; return to Fit.
- High-fps integer/fractional cadence choices and Source; change speed independently.
- Source switch, Back/Esc, and teardown while a surface single click is pending.

No computer-control skill, OS input injection, or simulated hands-on acceptance is used.

## Automated validation

The full Release suite passed 1,789 tests with zero skips on two complete runs.
The first full run had one intermittent pre-existing Browser recursive-folder fixture
failure: its tree selection was still null after its navigation/toggle waits. That
unmodified test group passed in isolation and both full reruns passed. The failure is
retained in the local TRX evidence under `artifacts/validation/player-199`.

Focused validation includes 54 Player/Browser/cadence tests, 21 tests after verifying
fullscreen through Home's actual ContentControl, native HWND identity/source retention,
double-click suppression, pan cancellation, all six loop speeds for each range context,
and bounded pan/Fit reset. The final backend/lifecycle group also exercises cancellation,
source switching, audio cleanup, and native playback against the last code changes.
No Browser production code was changed to address the intermittent fixture failure.
