## Proven journal cause and correction

Initial baseline `lf022-baseline.trx`: 30 passed, both interruption cases failed. Probe `lf022-native-signal-probe.trx`: both cases failed again. Parent PID 66464; children 74684 and 75204. Restart Manager identified the respective paused child as journal holder. Immediately after `Kill(entireProcessTree: true)` / `WaitForExitAsync`, zero-time native waits returned **258 / WAIT_TIMEOUT** for both retained process handles; exit time remained 1601-01-01. The first startup read failed sharing; later diagnostic reads verified 13/15 records ending at the intended boundary. This proves the fixture inspected before native process termination completed, rather than merely inferring an external scanner or production journal leak.

[Windows TerminateProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess) initiates asynchronous termination and requires waiting on the process object. [.NET 8 HasExited implementation](https://github.com/dotnet/runtime/blob/v8.0.0/src/libraries/System.Diagnostics.Process/src/System/Diagnostics/ProcessManager.Windows.cs) accepts the exit code before checking the native signal; the async wait can return through that observation. These contracts support the measured result.

The fixture now retains `child.SafeHandle` before termination and asserts a bounded native wait reaches `WAIT_OBJECT_0` before its **first** recovery inspection. Finally also joins that same owned process object. No journal polling, delay, retry, startup fallback, process-name termination or production change. The 10-second join bound follows the existing independent-process family's bound; it does not expand a failed test deadline. All original refusal, authoring/restore veto, journal integrity/intent, source/destination retention, released ownership, receiving-profile recovery and second-writer assertions remain.

Corrected interruption qualification passed 2/2. New controlled `LiveJournalWriterRefusesUnverifiedRecovery_ReleasedJournalStillRefusesInterruptedTransfer` deliberately retains the actual journal writer: startup remains CatalogUnavailable/PendingRecovery and refuses mutation/restore with unverifiable evidence; after release, a separate startup verifies interruption and still refuses authoring, with unchanged bytes/identity. ### What failed and what the measurement means

The complete original [CI log](https://github.com/jeremyrunningphotography/lightflow-studio/actions/runs/38456963160), original TRX and step/pin metadata are retained. `PlayerReviewBackendTests.cs:88` failed because one of 56 positive differences between successive `MediaPresentationTimestamp.Position.TotalSeconds` observations was 0.117, outside [0.032, 0.101]. This is a **source/media timestamp gap**, not 117 ms of wall-clock time. It is also not a direct assertion on every decoder-selected or renderer-presented frame. A separate assertion compares displayed media time with an elapsed wall clock over the existing 1.2-second observation window at speeds 0.5, 1 and 2; that assertion was not the reported failure. The retained failure did not identify which speed or the intermediate notification/render history.

The test generates a 160x90, 60000/1001 fps, six-second FFV1 MKV with the pinned FFmpeg, opens the real decoder, shows a WPF/native presentation on the private desktop, and enables 25 fps rational selection. It records service `FramePresented` notifications forwarded from Flyleaf `Player.CurTime`. The configured `UICurTime=PerFrame` does not turn those notifications into immutable, lossless per-frame records: at pinned Flyleaf commit `28f5dd4b3f4c09b6de37524a2e2cd7626f6d844e`, `Player.UpdateCurTime` writes shared `curTime`, then queues `UI(SetCurTime)`; `SetCurTime` reads the shared value when the action runs. [Utils.UI](https://github.com/jeremyrunningphotography/Flyleaf/blob/28f5dd4b3f4c09b6de37524a2e2cd7626f6d844e/FlyleafLib/Utils/Utils.cs) uses `BeginInvoke` at DataBind priority. Delayed dispatcher processing can therefore omit intermediate timestamp observations. Native decode/buffering, rendering and speed scheduling can also affect sample availability. This is a demonstrated pre-existing observation risk, not proof of the historical failing interleaving, nor permission to weaken the original assertions.

The whole playback class is in the existing `STA dispatcher tests` collection with `DisableParallelization=true`: the journal tests cannot execute concurrently with this class through ordinary xUnit collection parallelism. Native workers, engine reuse, earlier test effects and external machine load remain relevant. Candidate changes do not touch playback, selector, collection/test runner settings, dispatcher, private-desktop scripts, workflow or dependency inputs. Adding a test elsewhere can still affect global execution context/order, so source equality alone cannot categorically rule out every indirect influence.
