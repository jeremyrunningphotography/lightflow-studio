# Controlled backend responsibility and composition boundary

This describes future work if the owner selects route B. No production implementation is included or authorized.

| Owner | Responsibilities and validated seam |
|---|---|
| Shared product/application | Generation/lease cancellation, operation serialization, eligibility, In/Out, inclusive-to-exclusive frame boundary, marker/Subclip IDs/timing, review traversal, persisted volume/mute, Color intent and rotation, input targets and same-source fullscreen policy. Existing Windows code/tests remain authoritative. |
| Demux/decode adapter | Pinned LGPL FFmpeg; demux and codec lifetime, selected streams, raw rational PTS, stream-relative normalization, B-frame reorder, flush/drain/EOF, corruption/errors, hardware selection and software fallback. Native H.264 software/VideoToolbox corpus proven; HEVC only capability query/configuration, not decoded fixture. |
| Frame ownership | Queue immutable PTS + AVFrame/CVPixelBuffer/texture references. Next is next decoded frame. Reverse seeks to an earlier keyframe, decodes in presentation order, retains the greatest PTS strictly less than original and re-presents it. Expand bounded earlier windows when a GOP edge lacks predecessor; fail truthfully. Cache bounded GOP/frame windows for repeated reverse. Current proof starts from stream beginning for 1–3 s targets; long-duration indexing/cache/cancellation is not proven. |
| GPU/presentation | Preserve CVPixelBuffer until GPU completion; CVMetalTextureCache gives NV12 Y/UV planes. Respect range/matrix/transfer/chroma/pixel format; upload software fallback. Metal stages apply source+authored rotation exactly once, Camera then Creative, bypass, viewport and overlays. CPU/GPU trilinear/domain/rotation/readback proven on synthetic SDR BGRA; NV12 conversion/HDR/ICC/10-bit and end-to-end source orientation still require qualification. |
| Capture | Retained full-resolution texture and the same immutable PTS record; GPU completion before readback. Never pair capture with an unrelated playback-clock query. Offscreen GPU pixels proven; decoded PTS and GPU capture are not yet one integrated acknowledgement stream. |
| Audio adapter | FFmpeg decode/resample and selected streams; CoreAudio AudioQueue or justified AudioUnit; keep decode PTS, queue sample origin, driver/device latency and monotonic clock mappings explicit. Master clock drives video scheduling; pause/seek/step stop output and rebase only after settled source state. Tempo/pitch policy must match existing speed presets. PCM output/sample-clock components proven, integrated controlled AV sync remains open. |
| Device/lifecycle | Device format/latency change, output disconnect/restart, sleep/wake, end/drain, reopen, source cancellation, invalid handles, GPU command completion and release ordering. All require bounded admission and stale-result suppression. No physical device switch or sleep induced during owner's active desktop session. |

Future UI hosts an **NSView with a CAMetalLayer** or an agreed shared Metal texture bridge. The native proof gets 1280×720 drawables for a 640×360 logical view at scale 2 without showing a window. Resize to 320×180/640×360 leaves source texture intact. No permanently separate video window is required.

The host must propagate logical bounds, pixel backing scale and clip geometry explicitly. A native sibling/subview overlay is feasible; this is not proof that an arbitrary Avalonia control can overlay native airspace. Either render overlays into the shared texture, use an agreed native overlay layer, or qualify a framework texture-sharing path. Pointer hit-testing, keyboard focus, accessibility and gesture ownership belong to one semantic input route; native overlays must not intercept unrelated application shortcuts. X1 does not edit X3's workspace or choose M3's implementation.

Fullscreen should move/resize the same presentation/retained texture and source lease, avoid decoder/audio reopen and restore input/focus on exit. Actual macOS Spaces/fullscreen transitions are **unqualified**. Hidden offscreen geometry and drawable creation cannot establish that acceptance result.

Engineering estimate (inference, not approved budget): approximately **12–24 engineer-weeks** for a maintainable first backend plus media/lifecycle qualification, with additional shared UI/domain extraction and packaging work outside M1. Demux/decode/queue/reverse: 3–5 weeks; GPU/Color/capture: 3–5; audio/clock/device lifecycle: 3–6; host integration/failure qualification: 3–8. These ranges overlap and are uncertain; they exclude a new general media-engine feature set, new codecs, Intel and broad UI migration. Owner must approve scope/budget before production work.

To revise G1, qualify one integrated retained-frame PTS/capture/clock stream using these components, include rapid alternation and long-duration GOP boundaries, actual clipping/Retina/input/fullscreen, device restart/sleep-wake under agreed isolation, and In/Out/markers/Subclip/review adapters. Agree exact frame identity and numeric audio/pixel/performance limits with the owner. Do not lower semantics or create M4+ to hide these gaps.
