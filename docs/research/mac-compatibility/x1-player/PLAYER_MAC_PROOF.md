## Performance and distribution constraints

Single measured Metal command: 1080p ~0.797 ms, 4K ~3.126 ms with two LUTs/viewport; no steady-state scheduling claim. Native decode + full CPU transfer/hash + three seek scans: 1080p software 3.199 s / VideoToolbox 2.821 s; 4K 11.118 / 10.186 s. Maximum RSS: 1080p 45.3 / 57.0 MiB; 4K 145.5 / 181.2 MiB. User CPU seconds: 2.77/2.18 and 10.92/8.63 respectively. These are total multi-scan work, **not realtime decode throughput**. Production should retain CVPixelBuffer/Metal textures, avoiding per-frame CPU readback; integrated sustained playback, queues, latency and memory bounds remain to measure.

The tested stock libmpv bundle has GPL consequences incompatible with assuming Lightflow's current all-rights-reserved distribution can simply ship it. LGPL mpv configurations require dependency audit; a build switch alone does not resolve GPL dependencies. The minimal source-built FFmpeg demonstrates an LGPL-only dynamic route, not final distribution acceptance. Corresponding source/notices, relinking/reverse-engineering terms, exact dependency audit, signing/notarization and a complete supported media-format matrix remain required. [mpv Copyright](https://github.com/mpv-player/mpv/blob/v0.41.0/Copyright), [FFmpeg compliance](https://ffmpeg.org/legal.html).

## Owner gate and proposed revision

[Backend comparison](BACKEND_COMPARISON.md) explains the bounded libmpv insufficiency. Reverse stepping did pass; public atomic retained-pixel/source-PTS authority did not. No claim is made that every OpenGL integration or a future libmpv fork must fail. A new source-PTS hook plus qualification could change the result, but is not current proof.

[Controlled scope](NATIVE_BACKEND_SCOPE.md) assigns demux/decode, immutable frame ownership, exact reverse, GPU Color/capture, audio master clock and device/lifetime responsibilities. Future UI must host an NSView/CAMetalLayer or agreed shared-texture bridge; no permanent separate video window is required. Native overlay versus Avalonia airspace/input must be explicit.

Recommend **REVISE** before G1 acceptance: integrate one decoded PTS/retained texture/capture/presentation acknowledgement and audio-clock stream; exercise authored timing adapters, rapid alternating seek/step, long-duration GOP boundaries, actual native-host clipping/Retina/input/fullscreen, and device/restart/sleep-wake under agreed isolation. Agree budget and tolerances first. Proposed limits for owner discussion: zero wrong next/predecessor/retained frame; exact rational source PTS (only explicit 100 ns conversion rounding); SDR synthetic GPU error at most one 8-bit channel value; steady-state AV offset within ±20 ms and drift within 5 ms over ten minutes; speed-rate error within 1% over sufficiently long intervals; 4K/30 sustained processing within the 33.3 ms frame budget without unbounded queues. These are **recommendations, not accepted or proven limits**.

Estimated initial production backend + qualification: **12–24 engineer-weeks**, an uncertain engineering inference, excluding shared UI/domain extraction, packaging, Intel and extra formats. Component proof makes route B credible; it does not establish affordability against an owner-approved budget. Stop here for the combined G1/G2/G3 architecture review. No M4+ issue or production change is authorized by this result.
